# Task 4 — the first external check

**Level 2a achieved on 2026-08-02.** A hand-built FDA Module 1 backbone is
DTD-valid against FDA's own published DTD, checked by a parser that knows
nothing about RegOS.

| | |
|---|---|
| **Tool** | `xmllint`, libxml2 **20913** — bundled with macOS, `DTDValid` compiled in |
| **Specification** | FDA `us-regional` DTD **v3.3** |
| **Package under test** | [`ctd-987654/0000/`](ctd-987654/0000/) |
| **Level claimed** | **2a — structural.** Not 2b: no FDA business rule was checked |
| **Generated by RegOS** | **No.** Hand-built, deliberately — the target is proven before any code assumes it |

---

## Reproduce

```bash
cd docs/evidence/EPIC-007a/poc/ctd-987654/0000/m1/us
xmllint --valid --noout us-regional.xml
```

Silence is a pass. The DTD is resolved from the `DOCTYPE` declaration's relative
path, `../../util/dtd/us-regional-v3-3.dtd` — **the location the specification
requires it to occupy inside every sequence** (ICH Appendix 4, rows 372–376), not
a convenience path for this test.

Result:

```
VALID — parser accepted it
```

## The negative controls

**A validator that accepts everything proves nothing.** Both controls are
mutations of the same valid file, and both were chosen to test a finding rather
than to fail arbitrarily.

```bash
cd docs/evidence/EPIC-007a/poc/negative-controls
xmllint --valid --noout no-contacts.xml
xmllint --valid --noout operation-unchanged.xml
```

### 1. `no-contacts.xml` — the mandatory contact removed

```
element applicant-info: validity error : Element applicant-info content does not
follow the DTD, expecting (id , company-name , submission-description? ,
applicant-contacts), got (id company-name submission-description )
```

**S005's requirement, enforced from outside.** A sequence with no named person is
rejected — which is what `applicant-contacts (applicant-contact+)` means, and it
is not RegOS asserting it.

### 2. `operation-unchanged.xml` — an invented operation

```
element leaf: validity error : Value "unchanged" for attribute operation of leaf
is not among the enumerated set
```

**This is the ADR-045 finding, machine-checked.** There is nowhere in eCTD to say
*unchanged* — the enumeration is `new | append | replace | delete` and nothing
else. A cumulative dossier therefore *cannot* be transmitted as-is; the delta has
to be derived, and the format leaves no alternative.

> The product thesis did not just survive contact with the specification. **The
> specification has no way to express the thing ADR-045 refused to transmit.**

## What this run settled

| Question | Answer |
|---|---|
| Is Level 2a reachable without a commercial validator? | **Yes.** Free, offline, already installed |
| Does the parser actually reject? | **Yes** — twice, on the two findings that mattered |
| Is sequence `0000` legal? | **Yes.** The file validates with `0000`, so ADR-044's numbering is legal at 2a and the FDA-starts-at-0001 question is Level 3 convention |
| Is `Unchanged` renderable? | **No**, provably |

## What it did not settle

- **Nothing about `index.xml`.** Only the FDA regional backbone was checked. The
  ICH backbone needs `ich-ectd-3-2.dtd`, which is Appendix 8 of the ICH
  specification and is not yet in `spec/`.
- **No FDA business rule.** Whether `submission-id` correctly names the
  regulatory activity, whether an annual report must carry sub-type `report` — a
  DTD cannot express those. That is 2b, and it is carried.
- **Nothing about a package RegOS produced**, because RegOS did not produce this
  one. That is the point of doing it in this order.

## The gaps this file makes concrete

Every value below was typed by hand because RegOS cannot supply it:

| Element | Gap |
|---|---|
| `applicant-info/id` | no DUNS field — `999999999` placeholder used |
| `submission-id` `@submission-type` | **no regulatory activity** — the largest gap |
| `sequence-number` `@submission-sub-type` | no sub-type |
| `form` `@form-type` | no concept of the regulatory form |
| `applicant-contact-type` | FDA's vocabulary, not `ContactRole`'s — **mapped, never conflated** |
| `telephone`, `email` | both mandatory here; `Contact` must be checked |
| `application-number` | exists but is nullable and unset by every fixture |
